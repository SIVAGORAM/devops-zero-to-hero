Welcome to **Day 31**, the ultimate Capstone Project!

## 1. The Architecture
We are building the `python-devops-toolkit`, a robust CLI application that simulates a real DevOps workflow. It reads configurations from YAML, securely loads secrets from `.env`, processes system commands, runs HTTP health checks, interfaces with AWS via Boto3, and logs everything to a dedicated log file.

### Folder Structure
```text
python-devops-toolkit/
│
├── main.py                 # The CLI Entrypoint (argparse)
├── requirements.txt        # Project Dependencies
├── README.md               # Documentation
├── Dockerfile              # Containerization
├── .gitignore              # Git Ignore file (hides .env)
├── .env                    # Secure Secrets (AWS Keys, etc.)
├── config/
│   └── config.yaml         # YAML Configuration
│
├── devops/                 # The core logic package
│   ├── __init__.py
│   ├── system.py           # OS / Platform operations
│   ├── files.py            # Backup / Shutil operations
│   ├── api.py              # Requests / Health Checks
│   ├── aws.py              # Boto3 / EC2 Automation
│   ├── deployment.py       # Subprocess / Shell commands
│   └── logger.py           # Logging Configuration
│
├── backups/                # Generated by the tool
├── logs/                   # Generated by the tool
│
└── tests/                  # Pytest Suite
    ├── __init__.py
    └── test_system.py
```

## 2. Core Concepts Applied
This project ties together everything you've learned:
- **YAML & .env**: Decoupling configuration and secrets from source code.
- **Packages & Modules**: Organizing code into logical blocks (`devops.aws`, `devops.api`).
- **Standard Library**: Using `os`, `pathlib`, `shutil`, and `subprocess` for system automation.
- **Third-Party APIs**: Using `requests` to validate endpoints and `boto3` to manage AWS infrastructure.
- **Logging**: Ensuring every automation step writes a timestamped log to `logs/devops-tool.log`.
- **Argparse**: Providing a beautiful CLI interface so users can run `python main.py health --url https://google.com`.
- **Docker**: Packaging the entire tool into a lightweight container.

## 3. Advanced DevOps: CI/CD Pipeline Integration
A real DevOps toolkit must be tested automatically. We have added a `.github/workflows/ci.yml` file to the project. 
Whenever a developer pushes code to the `main` branch, GitHub Actions will spin up an Ubuntu runner, install Python, and run our `pytest` suite to ensure we didn't break any core automation functions!

---

## 4. Advanced DevOps: Packaging as a Global Binary (`setup.py`)
Right now, you have to run `python main.py system`. Real DevOps engineers package their scripts so they can be run as native shell commands.
We have added a `setup.py` file to the project. 

If you run:
```bash
pip install -e .
```
You can now run your automation tool from **anywhere** on your machine simply by typing:
```bash
devops-tool system
```
