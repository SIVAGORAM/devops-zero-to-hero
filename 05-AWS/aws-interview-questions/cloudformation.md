# AWS CloudFormation Interview Questions

AWS CloudFormation is the native Infrastructure as Code (IaC) tool for AWS. These questions will test your understanding of automated provisioning, stack management, and cloud architecture templates.

### 1. What is AWS CloudFormation?
**Answer:** AWS CloudFormation is a fully managed service that allows you to define, provision, and manage your AWS infrastructure as code (IaC). It enables you to create and update resources in a safe, predictable, and automated way using declarative configuration files.

### 2. What are the benefits of using AWS CloudFormation?
**Answer:** The primary benefits include: treating infrastructure as code (allowing for version control and code reviews), automating resource provisioning to eliminate human error, ensuring consistent deployments across multiple environments (Dev/Test/Prod), and easily replicating entire architectures globally.

### 3. What is an AWS CloudFormation template?
**Answer:** An AWS CloudFormation template is a formatted text file (written in either JSON or YAML) that serves as the blueprint for your infrastructure. It defines the exact AWS resources, configurations, properties, and dependencies required to build your architecture.

### 4. How does AWS CloudFormation work?
**Answer:** You write a declarative template, upload it to CloudFormation, and CloudFormation reads the file to figure out which AWS API calls to make. It automatically determines the correct dependency order to provision the resources, manages state, and rolls back if any resource fails to deploy.

### 5. What is a CloudFormation Stack?
**Answer:** A CloudFormation stack is the instantiated collection of AWS resources generated by a single template. When you deploy a template, you create a stack. You manage, update, and delete all the resources in that stack as a single, cohesive unit.

### 6. What is the difference between AWS CloudFormation and AWS Elastic Beanstalk?
**Answer:** CloudFormation is a foundational IaC tool that lets you provision *any* AWS resource at a low level (VPCs, subnets, IAM roles). AWS Elastic Beanstalk is a Platform-as-a-Service (PaaS) designed specifically for developers to quickly upload and run application code without worrying about the underlying servers. (Under the hood, Elastic Beanstalk actually uses CloudFormation to build its environments).

### 7. What is the purpose of a CloudFormation Change Set?
**Answer:** A Change Set allows you to safely preview how proposed modifications to a template will impact your currently running stack. It acts as a "dry run," showing you exactly which resources will be added, modified, or destroyed, ensuring that updates don't cause unintended production outages.

### 8. How can you create an AWS CloudFormation stack?
**Answer:** You can create a stack manually via the AWS Management Console, programmatically using the AWS CLI (`aws cloudformation create-stack`), or by using CI/CD tools (like AWS CodePipeline) and AWS SDKs. You must provide the template, a unique stack name, and any required input parameters.

### 9. How can you update an existing AWS CloudFormation stack?
**Answer:** You update a stack by modifying the local template file or passing new parameter values, and then submitting it to AWS via the console or CLI (`aws cloudformation update-stack`). CloudFormation will compare the new template to the running stack and apply only the necessary changes.

### 10. What is the CloudFormation rollback feature?
**Answer:** If CloudFormation encounters an error while creating or updating a stack (e.g., you hit an account limit, or a resource is misconfigured), it will automatically trigger a **rollback**. This deletes all partially created resources and reverts the stack to its last known stable state, preventing corrupted infrastructure.

### 11. How does AWS CloudFormation handle dependencies between resources?
**Answer:** CloudFormation is smart enough to handle implicit dependencies (e.g., if an EC2 instance references a Security Group ID using the `!Ref` function, it knows to build the Security Group first). For explicit dependencies that it cannot infer, you use the `DependsOn` attribute.

### 12. What are CloudFormation Intrinsic Functions?
**Answer:** Intrinsic functions are built-in functions used within templates to dynamically assign values at runtime. Common examples include `!Ref` (to get a resource ID), `!GetAtt` (to get an attribute like an ARN or DNS name), and `!Sub` (to substitute variables into a string).

### 13. How can you perform conditionals in CloudFormation templates?
**Answer:** You define conditions in the `Conditions` section using intrinsic functions like `!Equals`, `!If`, `!Not`, and `!Or`. For example, you can create a condition that only provisions a high-performance Database Instance if the `Environment` parameter equals `Production`.

### 14. What is the CloudFormation Designer?
**Answer:** The CloudFormation Designer is a visual, drag-and-drop tool available in the AWS Console. It allows you to design architecture diagrams visually, and it automatically generates the underlying JSON/YAML CloudFormation template for you.

### 15. How can you manage secrets in CloudFormation templates?
**Answer:** You should never hardcode database passwords or API keys in your templates. Instead, you use AWS Systems Manager (SSM) Parameter Store or AWS Secrets Manager to store the secrets securely, and reference them dynamically in the template using dynamic references (e.g., `{{resolve:secretsmanager:MySecret}}`).

### 16. How can you provision custom resources in CloudFormation?
**Answer:** If you need to provision something that CloudFormation doesn't natively support (e.g., seeding a database with initial tables, or calling a third-party API), you can create a **Custom Resource**. This triggers an AWS Lambda function during stack creation, executes your custom Python/Node code, and reports success/failure back to CloudFormation.

### 17. What is Stack Drift in AWS CloudFormation?
**Answer:** Stack Drift occurs when a human manually logs into the AWS console and changes a resource (like opening a port on a Security Group) that is managed by CloudFormation. The real-world resource has "drifted" from the code definition. You can run Drift Detection to identify and remediate these violations.

### 18. How does CloudFormation support rollback triggers?
**Answer:** Rollback triggers allow you to integrate CloudWatch Alarms directly into your stack deployment. If you update a stack and the update causes your application's error rate to spike (triggering the CloudWatch Alarm), CloudFormation will automatically halt the deployment and roll back the entire stack.

### 19. Can AWS CloudFormation be used for creating non-AWS resources?
**Answer:** Yes, by using CloudFormation Custom Resources (Lambda-backed) or by utilizing the new **CloudFormation Public Registry**, you can manage non-AWS resources, SaaS platforms, or third-party integrations directly alongside your AWS infrastructure.

### 20. What are CloudFormation StackSets?
**Answer:** StackSets are an enterprise-level feature that allows you to deploy and manage CloudFormation stacks across multiple AWS Accounts and multiple Regions simultaneously from a single central administrator account. It is heavily used in AWS Organizations for baseline security deployments.
